# IntelliTwin AI — Scientific Machine Learning Validation Report

This report documents the rigorous empirical evaluation, methodology, data provenance, and explainability validation for the **IntelliTwin AI** machine learning intrusion detection subsystem.

---

## 1. Dataset Provenance & Integrity Audit

### 1.1 Authentic UNSW-NB15 Benchmark
The evaluation is conducted on the authentic **UNSW-NB15** network benchmark dataset generated by the Cyber Range Lab of the Australian Centre for Cyber Security (ACCS) at the University of New South Wales (Moustafa & Slay, 2015).

- **Official Source**: Australian Centre for Cyber Security (ACCS)
- **Raw File Details**:
  - `UNSW_NB15_training-set.csv`: 32,293,018 bytes, SHA-256: `bec7dd5ec88dc2a0ccc7a07879d338395ed7421750f675fd0339e07dfe0648fa`
  - `UNSW_NB15_testing-set.csv`: 15,380,800 bytes, SHA-256: `734fe6642edf758f7c94d7d9149426b49d202fe8e7bf0bef47392489c3c0a559`
- **Feature Schema**: 42 network flow attributes including transport protocol (`proto`), connection state (`state`), flow duration (`dur`), packet counts (`spkts`, `dpkts`), byte counters (`sbytes`, `dbytes`), inter-arrival times (`sintpkt`, `dintpkt`), TCP window sizes (`swin`, `dwin`), and connection window aggregations (`ct_srv_src`, `ct_dst_ltm`).
- **Target Label**: `label` (0 = Normal, 1 = Attack/Anomaly).

### 1.2 Investigation of Previous "100.0% Accuracy" Claim
In earlier prototypes of this project, an accuracy of 100.0% was reported. A forensic audit revealed the root cause:
1. The original automated dataset fetcher encountered HTTP 404 errors on legacy UNSW mirror URLs and silently dropped into a synthetic data generator fallback (`download_unsw.py`).
2. The synthetic generator sampled feature values using disjoint Poisson and uniform distributions (`np.where(labels == 0, np.random.poisson(...), ...)`).
3. This eliminated real-world class overlap, creating trivial linear separability and yielding a mathematically artificial 100.0% accuracy.
4. **Resolution**: The synthetic generator was decommissioned. Authentic UNSW-NB15 CSV files were ingested, validated via cryptographic checksums, and partitioned with strict stratification.

### 1.3 Evaluation Protocol & Partitioning
- A stratified sample of **25,000 authentic network flow records** was drawn with identical class balance (68.3% attacks, 31.7% normal).
- **Split**: 80% Training (20,000 samples) and 20% Held-Out Testing (5,000 samples).
- **Zero Leakage**: All scalers and encoders were fit **exclusively** on the 20,000 training records and applied as transforms to the held-out test records.

## 2. Preprocessing & Feature Engineering Pipeline

The preprocessing architecture uses an immutable `ColumnTransformer` (`ml-engine/preprocessing/preprocessor.py`):
1. **Numerical Pipeline**:
   - Outlier resistance via `RobustScaler(with_centering=True, with_scaling=True, quantile_range=(25.0, 75.0))`.
   - Missing and non-finite value imputation via `SimpleImputer(strategy='median')`.
2. **Categorical Pipeline**:
   - Categorical attributes (`proto`, `state`) processed via `OrdinalEncoder(handle_unknown='use_encoded_value', unknown_value=-1)`.
3. **Target Leakage Safeguards**:
   - Metadata columns (`id`, `attack_cat`) and target `label` are stripped prior to feature ingestion.

---

## 3. Model Architecture & Training Methodology

Three distinct algorithmic paradigms were benchmarked:
1. **Extreme Gradient Boosting (XGBoost)**: Gradient-boosted decision trees using regularized objective functions with tree depth 6, learning rate 0.1, and 150 estimators.
2. **Random Forest**: Ensemble of 150 bootstrap-aggregated decision trees with Gini impurity splitting and random feature sub-sampling ($\sqrt{M}$).
3. **Isolation Forest**: Unsupervised recursive partitioning isolating anomalies based on path lengths in binary trees.

Model selection was governed by **5-Fold Stratified Cross-Validation on the 20,000 training samples**. The held-out 5,000 test set was evaluated once post-training.

## 5. Explainable AI (SHAP) Validation

Local explainability is achieved using `shap.TreeExplainer`:
- **Additive Feature Attribution**: For every packet $x$, the model prediction is decomposed into additive feature contributions:
  $$f(x) = \phi_0 + \sum_{i=1}^M \phi_i(x)$$
  where $\phi_0$ is the base expected value ($0.683$) and $\phi_i$ is the marginal contribution of feature $i$.
- **Dominant Features in Network Attacks**:
  - `ct_dst_src_ltm` & `ct_srv_dst`: High connection concentrations across short time intervals drive positive $\phi$ pushes (+0.15 to +0.35) during reconnaissance and DoS attacks.
  - `rate`: Packet rates exceeding 50,000 pkts/s provide strong positive attribution for volumetric floods.
  - `sttl` (Source Time to Live): Extreme TTL variances indicate OS fingerprinting and spoofed ingress.

## 6. Risk Calibration & Uncertainty Quantification

In `backend/app/services/ml_service.py`:
- Raw classifier probability $p = P(\text{Attack})$ is calibrated into an operational Risk Score:
  $$\text{RiskScore} = \text{round}(p \times 100, 1)$$
- **Uncertainty Quantification**: The model computes epistemic uncertainty based on probability entropy:
  $$U(p) = 1.0 - 2 \cdot |p - 0.5|$$
  - When $p \approx 0.5$, uncertainty reaches $1.0$ (High Ambiguity).
  - When $p \to 1.0$ or $p \to 0.0$, uncertainty approaches $0.0$ (High Confidence).
- **Severity Mapping**:
  - $0 \le \text{Risk} < 25$: `LOW`
  - $25 \le \text{Risk} < 60$: `MEDIUM`
  - $60 \le \text{Risk} < 85$: `HIGH`
  - $85 \le \text{Risk} \le 100$: `CRITICAL`
